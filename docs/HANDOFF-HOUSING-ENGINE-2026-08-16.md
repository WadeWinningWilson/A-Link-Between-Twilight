## 4. LOAD-BEARING ASSUMPTIONS

**§801 / provenance — the label is a GATE INPUT, not decoration.** A NonMatching
donor body IS admissible as a behavioural spec (ruled 2026-08-16 on a
completeness test with a live negative control). **Work derived from
`processor.cpp`/`resource.cpp` must NEVER carry `byte-true: BYTE-TRUE` — it
stays `DIVERGENT`.** Enforced twice, independently: the Integrator refuses a
mislabelled row at the build gate, `row_store.py` refuses it at filing.

**The seam law, and it holds in both directions:** CALL receiver symbols freely;
DEFINE none of theirs. The `WwJMessage::` rename is closed under itself — every
donor definition is `JMessage::`-qualified or in an anonymous namespace, so
relocating the namespace relocates 100% of externally visible symbols.

**The plugin includes ZERO receiver headers.** It reaches the receiver through
50 `DEFINE_HOOK_SYMBOL`/`s_hook->resolve` sites, by mangled name at runtime.
That is the design: no thunk into the host, version-independent. **Do not
"simplify" it by including a game header** — it also does not compile (dies in
`SSystem/SComponent/c_xyz.h:166`).

**State comes IN as a parameter; the tier never fetches it.** `WwDMesg::doTag`
takes a `TagState` + `EmitFn`. The alternative — resolve `g_dComIfG_gameInfo`
and read a struct offset — is **the exact shape that produced the `mMsgGroup`
crash** (field at 0x28 out of a 0x20 struct, every WW stage load). Unnecessary:
`dExtDmesg_paginate` is receiver code and already calls
`dComIfGs_getPlayerName()` on stock at `d_ext_dmesg.cpp:426`.

**§308 is the HOST, `WwJMessage::` is the ENGINE.** 1,042 lines = 76 engine +
916 host. Porting the engine does not invalidate §308; 92% stays. Additive.

**The colour fork edit is deliberate and is ON THE OWED LIST.**
`d_ext_dmesg.cpp` was ALREADY a fork-only WW file ALREADY containing the wrong
`kWwColor` (7 of 9 entries disagree with the donor's shipped `color.bmc`, and
colour is 58.9% of corpus tags). It corrects an existing fork leg rather than
adding one — but it will NOT travel plugin-side. Retire it only when a
plugin-reachable consumer exists.

**A `nullptr` channel returns FALSE, never a default.** Every wired arm guards
and falls through so the base layer warns by group/code. This is not defensive
padding: the anime stub was `getMesgAnimeTagInfo() { return 0xFF; }` beside an
empty setter — a channel that could never carry a value, losing every tag

## 5. ERROR CLASSIFICATION

**The dominant failure mode this session was not being wrong — it was being
right about a measurement and wrong about what it meant.** Six instances.

1. **A validated oracle pointed at the wrong property is still wrong.** I
   confirmed my working hook symbols were in `exports.def` before trusting it —
   which proved the table ACCURATE, not that it ANSWERED MY QUESTION. Ask "what
   does this artifact record?" before "is it correct?"
2. **An inherited premise inside a VERIFICATION HARNESS inverts the verdict.** I
   typed another lane's enum order into my check script's label table and
   announced correct code was broken.
3. **A measured fact + a plausible reading is not a finding.** High-byte density
   proves non-ASCII, never WHICH non-ASCII (`zel_01`).
4. **"The donor has no data for X" must be measured PER X.** Interior *names*
   are genuinely absent (measured twice); interior *parentage* looked identical
   and was fully present in `SCLS` — 54 stages, zero authoring.
5. **Two lanes in one file: "it compiled" ≠ "my function is the one running."**
   A same-name definition at a different scope produces NO duplicate-symbol
   error and silently shadows. Detect with a namespace-depth walk, not grep.
6. **Never truncate an enumeration you are about to reason over.** Cost me the
   `Ojhous` claim one row after I invoked that exact lesson at another lane.

**Two mechanical hazards that cost real time:**
- **Heredocs eat backslashes.** A Windows path split a CALLS row across two
  lines (`\res` → CR); `'\0'` became a LITERAL 0x00 BYTE in shipped source.
  **Write text with the Write tool to a scratchpad file and `open()` it.** Scan
  for control bytes after any scripted write.
- **`.bat` files must be CRLF** or cmd token-splits them (`'cho' is not
  recognized`).

## 7. THE MONITOR — a working exemplar for the lanes

**Boot watching is NOT this lane's job** (user ruling 2026-08-16, mid-session:
*"Your job is not to watch boots of dusklight. That is integrators job"*). Mine
was killed. **The pattern below is what other lanes should copy for their OWN
surfaces** — it is the version that survived the failure that killed the first.

### The failure it fixes

My boot watch **died at 11:31 and 10 boots ran unobserved.** Cause: it LATCHED a
log file, that file rotated away, and the loop died. The spec said *"re-latches
when a newer log appears"* — which covers the directory growing, **not the
current file vanishing.**

### The three properties, which are NOT the same thing

This is the transferable part. Three lanes were bitten by three different ones
in one day:
- **LIVENESS** — is the loop running? (my board watch was alive the whole time,
  which is exactly why the dead boot watch stayed invisible)
- **COVERAGE** — does the filter match what you care about?
- **DELIVERY** — do events reach the conversation? (History/Bridge's watcher was
  alive AND covering and fired **into a file nobody read** — *"a background
  watcher that never exits raises no notification"*)

**Check each watch separately. Never infer one watch's health from another's
traffic.**

### The working shape

```bash
L="<log dir>"; P="<scratchpad>/pulse_<name>.json"
FILT='<the lines you would ACT on — success AND failure signatures>'
cur=""; pos=0
while true; do
  # RE-DERIVE the newest file EVERY poll. Never hold a latch: the file you
  # latched can be deleted, and that is what killed the last one.
  new=$(ls -t "$L"/<pattern> 2>/dev/null | head -1)
  if [ -n "$new" ] && [ "$new" != "$cur" ]; then cur="$new"; pos=0; fi
  if [ -n "$cur" ] && [ -f "$cur" ]; then
    sz=$(wc -c < "$cur" 2>/dev/null || echo 0)
    [ "$sz" -lt "$pos" ] && pos=0            # truncation -> reset, not negative
    if [ "$sz" -gt "$pos" ]; then
      tail -c +$((pos+1)) "$cur" | grep -E --line-buffered "$FILT" | head -40
      pos=$sz
    fi
  elif [ -n "$cur" ]; then
    cur=""; pos=0                            # vanished -> re-latch, never die
  fi
  # PULSE EVERY LOOP. This is the only thing that makes death detectable.
  printf '{"watch":"<name>","ts":%s,"interval":5,"cur":"%s","pos":%s}\n' \
    "$(date +%s)" "$(basename "${cur:-none}")" "$pos" > "$P"
  sleep 5
done
```

### Non-negotiables

- **Pulse every loop, to a file.** Liveness is `now - ts` vs `3 x interval`.
  Mine read 2h43m stale against a 5-second poll — dead by four orders of
  magnitude, and visible at a glance next to a healthy sibling's 18 seconds.
- **`grep` needs `--line-buffered`** or matches sit in the buffer unseen.
  `head` cannot flush at all.
- **The filter must match FAILURE, not just success.** A monitor that greps only
  the happy path is silent through a crash, and silence looks identical to
  "still running".
- **Orphan-scan after every stop.** `TaskStop` returning success is not proof —
  check the pulse file has actually stopped advancing.
